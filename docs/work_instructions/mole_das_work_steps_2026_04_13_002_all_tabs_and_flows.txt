Purpose

- This document completes the workstep format started in `worksteps_2026_04_13_001.txt`.
- The format is intentionally kept as a plain operational outline with major sections, bullets, and nested entries.
- This document covers:
	- every current Wizard navigation tab
	- the major DAQ Runner operating environments
	- the main operator and support workflows
	- testing flow paths from Diagnostics-only through formal FTIR Method 301 comparison

New Project

- From the Welcome Screen, navigate to "Project Configs (Hub)"
	- Welcome
		- The Welcome tab is the routing tab
		- It is used to:
			- start a new project
			- load an existing configuration
			- review the recommended setup order
		- The normal setup order is:
			- Project Configs (Hub)
			- Job Intake (QA Routing)
			- Source Details
			- Pollutants
			- QA/QC
			- Test Matrix
			- Site Conditions
			- Reference / Audit FTIR (if used)
			- Sample System
			- Fuel Analysis
			- Regulatory
			- Save + Apply Config
			- DAQ Runner (Test) or DAQ Runner (SIM)

	- Project Configs (Hub)
		- The Job ID is a unique MOLE-DAS generated project number
		- The Job ID format remains:
			- YYYY_MM_DD_HHMM
		- The primary project/session folder now uses:
			- JobID_ProjectName_Site-Facility_Operator_Asset-Unit-ID
		- Enter the following core project identifiers:
			- Job ID
			- Project Name
			- Site / Facility
			- Operator
			- Asset / Unit ID
		- Session Intent
			- Record Data is selected if the session should persist DAQ evidence
			- Tokenize is selected if full provenance / traceability is desired
			- Diagnostics-only is selected for tuning, troubleshooting, or non-compliance verification use
			- May Support Compliance is selected when the project may support compliance or formal reporting
			- Diagnostics-only and May Support Compliance are mutually exclusive
		- Fuel Category
			- Primary selections include:
				- NG Natural Gas
				- DSL Diesel Fuel
				- DG Dual-Fuel Blend
				- BG Biogas
				- RFG Refinery Fuel Gas
				- OT Other
			- If "Capture Fuel Analysis" is selected, the User is expected to complete the Fuel Analysis tab
		- Arcade Soundtrack
			- Toggle soundtrack ON/OFF
			- Select Auto mode behavior
			- Adjust volume
			- Review active track
		- Validation Test Plan
			- This section is used when the project is a validation or FTIR comparison project
			- Session Type options include:
				- STANDARD_TEST
				- FTIR_VALIDATION
			- Validation Mode options include:
				- NONE
				- METHOD_301_INFORMED_COMPARISON
				- METHOD_301_FORMAL
			- Comparator Method is used to describe the external comparator method or protocol
			- FTIR Vendor Profile is used to pre-seed the downstream FTIR validation workflow
			- Comparator Label allows a project-specific comparator name
			- Timestamp Master Clock identifies the authoritative clock for alignment
			- Planned Set Count is used for FTIR side-by-side planning
			- Planned Run Minutes and Purge Minutes establish cadence defaults
			- Purge Required and Bias Required define cadence checkpoints expected in the live runner
			- Lead Scientist, Peer Reviewer, and Final Approver identify validation assignments
			- Plan Notes allow project-specific validation planning notes

Testing Flow Paths

- Diagnostics-only - Test Environment
	- Use this when the goal is troubleshooting, tuning, or non-compliance verification
	- Recommended flow:
		- Welcome
		- Project Configs (Hub)
			- set Diagnostics-only
			- leave May Support Compliance off
		- Source Details
		- Pollutants
		- Site Conditions
		- Sample System
		- Fuel Analysis
		- Regulatory only if comparison limits are desired
		- Save + Apply Config
		- DAQ Runner (Test)
		- In the diagnostics runner:
			- complete Diagnostics Verification when applicable
			- review Method 19 inputs / outputs
			- review Calculation Audit / Provenance
			- use Diagnostics Print Panel for non-compliance artifact export
	- Expected outputs:
		- diagnostics snapshots
		- calculation audit JSON/CSV
		- no formal report-pack deliverable

- Diagnostics-only - SIM Environment
	- Use this when the goal is operator training or sandboxed diagnostics rehearsal
	- Recommended flow:
		- Project Configs (Hub)
			- set Diagnostics-only
		- complete only the tabs needed for the simulated source behavior
		- Save + Apply Config
		- DAQ Runner (SIM)
		- use the diagnostics-only training shell
	- Expected outputs:
		- sandboxed diagnostics behavior
		- no compliance support
		- no formal report-pack path

- Standard Recorded Test - No FTIR
	- Use this when the project is a normal recorded MOLE test without FTIR reference or validation
	- Recommended flow:
		- Welcome
		- Project Configs (Hub)
			- set Record Data
			- set Tokenize if full provenance is desired
		- Job Intake (if the project may support compliance)
		- Source Details
		- Pollutants
		- QA/QC
		- Test Matrix
		- Site Conditions
		- Sample System
		- Fuel Analysis
		- Regulatory (if limits/rules are needed)
		- Save + Apply Config
		- DAQ Runner (Test)
		- execute runs and worksteps
		- use Report Builder for formal package/report generation when needed
	- Expected outputs:
		- report_pack_v1
		- final_report_v1
		- package approval/signoff path if formal deliverables are used

- Standard SIM / Training Test - No FTIR
	- Use this when training or rehearsing the standard recorded workflow without live acquisition
	- Recommended flow:
		- configure the session as a standard non-diagnostics session
		- Save + Apply Config
		- DAQ Runner (SIM)
		- review simulated pollutant behavior, worksteps, and Method 19 sections
		- optionally practice Report Builder metadata entry and package review

- Compliance-support Recorded Test
	- Use this when the project may support a compliance-style deliverable
	- Required flow additions:
		- Project Configs (Hub)
			- set May Support Compliance
		- Job Intake (QA Routing)
			- complete checklist
		- Pollutants / QA/QC / Test Matrix
			- confirm method/profile/tolerance logic
		- Fuel Analysis
			- complete and verify
		- Regulatory
			- enter selected rules
			- enter basis-aware limits
		- Save + Apply Config
		- DAQ Runner (Test)
			- complete QA/QC, run workflow, and post-cal workflow as required
		- Report Builder
			- enter report metadata
			- lock session review
			- sign off package review
			- build report pack and final report
	- Expected outputs:
		- report pack
		- final report
		- package approval and deliverable readiness states

- FTIR Reference / Audit Companion Workflow
	- Use this when FTIR is a reference or audit data source, but not a formal side-by-side validation package
	- Recommended flow:
		- configure the standard recorded or compliance-support workflow
		- complete Reference / Audit FTIR
			- enable FTIR ingest
			- select role
			- select method
			- set parser/file inputs
			- set offsets if applicable
		- Save FTIR Into Session
		- Save + Apply Config
		- DAQ Runner (Test)
			- use Reference / Audit FTIR section
			- review side-by-side alignment if relevant
			- review FTIR method worksteps
		- Build the formal report if the project requires it
	- Expected outputs:
		- FTIR reference/audit evidence in the session package
		- optional offset trace
		- FTIR context in the final report

- FTIR Side-by-Side Informed Comparison
	- Use this when the project compares MOLE and FTIR side-by-side, but the project does not satisfy the full formal Method 301 structure
	- Recommended setup flow:
		- Project Configs (Hub)
			- Session Type = FTIR_VALIDATION
			- Validation Mode = METHOD_301_INFORMED_COMPARISON
			- complete Validation Test Plan
		- Source Details
		- Pollutants
		- QA/QC
		- Test Matrix
			- define planned runs and cadence
		- Site Conditions
		- Sample System
		- Fuel Analysis
		- Regulatory as needed
		- Save + Apply Config
	- Recommended runner flow:
		- DAQ Runner (Test)
		- Report Builder
			- FTIR Side-by-Side Validation
				- select vendor profile
				- load FTIR file
				- set timestamp column / delimiter / analytes
				- use template folder / import template / alignment worksheet as needed
				- refresh FTIR validation preview
				- review alignment QA
				- apply offset sweep if needed
				- accept/reject comparison sets
				- review exclusions
				- lock FTIR review
				- sign off FTIR validation
		- Build report
	- Expected outputs:
		- informed comparison package
		- reviewer workbook
		- locked snapshot
		- signed FTIR appendix package
		- final report with informed-comparison basis
