Step 1.0 - Open run_wizard.bat

		Use the Wizard as the primary project-authoring interface for MOLE-DAS.

		Recommended launcher options:

			1. run_wizard.bat - standard Wizard launcher.
			2. run_wizard_console.bat - console-backed Wizard launcher for troubleshooting.

		*The DAQ Runner launch tabs are not enabled until the session is saved/applied.

Step 1.1 - Welcome

		The Welcome tab is a quick-routing tab. It summarizes the recommended setup flow:

			1. Project Configs
			2. Source Details
			3. QA/QC
			4. Test Matrix
			5. Site Conditions
			6. Fuel Analysis
			7. Save + Apply Config
			8. DAQ Runner

		Use "Go to Project Configs" to begin a new setup.

Step 2.0 - Existing Session vs New Session

		If you are creating a new project instance (emissions source profile), use "Project Configs (Hub)".

		If you are continuing or revising an existing setup, use "Load Existing Config...".

		*When an existing configuration file is loaded, the prior session data is restored into the Wizard. The operator may then update entries such as the test matrix, pollutant selections, QA/QC details, FTIR settings, hardware selections, site/weather values, regulatory limits, or other project-specific changes.

Step 2.1 - Project Configs (Hub)

		In "Project Configs (Hub)", enter the core project identifiers:

			1. Job ID
			2. Project Name
			3. Site / Facility
			4. Operator
			5. Asset / Unit ID

		These entries define the project/session identity used by downstream tabs and exports.

Step 2.2 - Session Intent

		Session intent controls how the session behaves and what governance logic is applied.

		The available selections are:

			1. Record Data
			2. Tokenize
			3. Diagnostics-only
			4. May Support Compliance

		Intent behavior:

			1. Record Data - session is configured to retain DAQ activities and related evidence.
			2. Tokenize - session provenance and evidence immutability features are enabled.
			3. Diagnostics-only - the launch path becomes diagnostics-only; compliance support is disabled.
			4. May Support Compliance - indicates the project may be used for compliance or compliance support.

		*Diagnostics-only and compliance support are mutually exclusive.

Step 2.3 - Fuel Category

		Fuel category allows the operator to classify the source fuel basis:

			1. NG - Natural Gas
			2. DSL - Diesel
			3. DG - Dual Fuel
			4. BG - Biogas / Digester Gas
			5. RFG - Refinery Fuel Gas
			6. OT - Other

		The tab allows:

			1. direct fuel button selection
			2. fuel dropdown selection
			3. optional "Capture Fuel Analysis" selection

		*Fuel Analysis is strongly recommended for NG, BG, DG, and any project with site-specific fuel information.

Step 2.4 - Arcade Soundtrack

		MOLE-DAS includes a soundtrack utility. The operator may:

			1. Enable or disable soundtrack playback.
			2. Choose Auto mode behavior.
			3. Adjust Volume.
			4. Review the active track.

			4. Acknowledge run-to-run fuel flow variation

Step 7.6 - Exhaust Flowrate Determination

		Select how exhaust flow will be determined.

		The available setup patterns include:

			1. Fuel-flow-driven Method 19-based Qd estimation
				a. Fuel flow
				b. Units
				c. O2 dry % (optional)
			2. EPA Method 2 / measured stack flow
				a. EPA Method selection
			3. Stoichiometric fuel crosswalk with direct heat input
				a. Basis
				b. O2 dry % (optional)
				c. Heat input (MMBtu/hr)
			4. Stoichiometric fuel crosswalk from rated power and heat rate
				a. Rated power (hp)
				b. Load fraction
				c. Heat rate (Btu/hp-hr)
			5. Stoichiometric fuel crosswalk from rated power and BSFC
				a. Rated power (hp)
				b. Load fraction
				c. BSFC (lb/hp-hr)
				d. Fuel LHV (optional)

		*The actual run-level values may be entered or refined later in the DAQ Runner.

Step 7.7 - Stack / Duct Geometry (EPA Method 1/2)

Step 23.0 - DAQ Runner (Test)

		"DAQ Runner (Test)" launches the production/test runner using the applied session.

		If "Diagnostics-only" is NOT selected:

			1. this launches the full formal runner
			2. hardware/plugin acquisition may be used

		If "Diagnostics-only" IS selected:

			1. this launches the diagnostics-only shell
			2. compliance support is disabled
			3. report-pack usage is disabled
			4. QA/QC trending is disabled

Step 24.0 - DAQ Runner (SIM)

		"DAQ Runner (SIM)" launches the simulator/training runner.

		If "Diagnostics-only" is NOT selected:

			1. this launches the formal training/simulation runner

		If "Diagnostics-only" IS selected:

			1. this launches the diagnostics-only training shell
			2. the session remains sandboxed and excluded from compliance support

Step 24.1 - Diagnostics Verification / Responsibility

		When diagnostics mode is used, the operator/technician is responsible for:

			1. performing pre-test calibration verification / linearity assessment
			2. performing post-test calibration verification / linearity assessment
			3. documenting those activities before relying on diagnostics outputs where pollutant limits are in scope
